# Промти для ШІ-агентів

Головний промт проєкту: [`/CLAUDE.md`](../../CLAUDE.md). Він завантажується автоматично в кожній сесії Claude Code і є обов'язковим контекстом.

Промти за напрямками не дублюються тут: **розділ 0 «Контекст для ШІ-агента» кожної специфікації** у [`docs/specs/`](../specs/) і є промтом для роботи над цим напрямком. Так промт і вимоги живуть в одному файлі й не розходяться.

## Як поставити задачу агенту

Скопіюйте й заповніть:

```
Задача: <одне речення, що має бути зроблено>
Напрямок: docs/specs/NN-<назва>.md (прочитай розділ 0, потім вимоги FR-NN-x, які закриваємо)
Вимоги, які закриваємо: FR-NN-a, FR-NN-b
Обмеження: <що не чіпати; чи потрібен ADR; чи є дизайн-макет у 03>
Результат: <код + тести + знімки екрана світла/темна | документ | ADR>
Перевірка: <команди або чеклист, якими підтверджуємо готовність>
```

## Порядок читання для нового агента (30 хвилин)

1. `CLAUDE.md` (5 хв).
2. `docs/SPEC.md` (10 хв).
3. `docs/decisions/2026-09-25-interview.md`, розділи 1-6 (10 хв).
4. Розділ 0 специфікації свого напрямку (5 хв). Для UI-задач додатково `docs/specs/02-design-system.md` розділи про токени й компоненти та `design/preview/index.html`.

## Спеціалізовані ролі

| Роль | Що читає додатково | Що повертає |
|---|---|---|
| Архітектор | 01, 15, ADR | ADR-чернетку, діаграму, план змін по шарах |
| Дизайнер інтерфейсу | 02, 03, tokens.json, preview | wireframe і стани в 03, оновлення токенів, HTML-прев'ю |
| Розробник MAUI | 01, 03, 02 (компоненти), 06/07 за потреби | код Presentation/Application з тестами і знімками |
| Розробник Swift-віджетів | 04, 02 (віджети), 01 (контракт App Group) | Swift-код, знімки з CI, оновлення контракту |
| Розробник сервера | 09, 10, 01 | код модуля з тестами Testcontainers, OpenAPI diff |
| Контент-інженер | 08, 12, glossary | промти генерації, звіти рецензування, пакети |
| Рев'юер | усе вище + 15 | список дефектів з посиланням на вимоги, без виправлень |

## Правила для всіх ролей

- Знайшов суперечність між документами: зупинись, повідом, запропонуй ADR. Не виправляй мовчки.
- Не вигадуй факти про платформи чи версії: перевір у `docs/research/` або в офіційній документації з посиланням.
- Звітуй чесно про неперевірене (наприклад, iOS локально не запускається).
