# 0015. Два лічильники показів: заплановані та підтверджені

| Поле | Значення |
|---|---|
| Статус | Accepted |
| Дата | 2026-09-27 |
| Рішення журналу | T5, Q1 |
| Специфікації | 06, 04, 05, 13 |

## Контекст

Продукт обіцяє статистику «скільки разів слово показано», але iOS не повідомляє, чи віджет справді бачили; Android надає impressions лише з 16.1. Показувати лише заплановані покази означало б обманювати користувача.

## Варіанти

1. Лише заплановані (оптимістично).
2. **`exposureScheduled` (кожен запланований слот таймлайну, сповіщення, сесійна зміна) та `exposureConfirmed` (натискання віджета, дія у сповіщенні, перегляд у застосунку, кнопка «наступне», Android impression). Користувачу показуємо підтверджені як «переглянуто», заплановані як оцінку.**
3. Лише підтверджені. Втрачаємо сигнал для планування.

## Рішення

Варіант 2. Обидва лічильники зберігаються у ExposureRecord і впливають на фазу «знайомство» з різною вагою (підтверджений показ важить більше; точні ваги у специфікації 06).

## Наслідки

Мікрокопі статистики розрізняє «показано» і «переглянуто». Заплановані покази агрегуються по днях перед синхронізацією, щоб не роздувати журнал.
