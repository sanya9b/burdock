# 0001. .NET MAUI та Clean Architecture як основа мобільного застосунку

## Контекст

Один розробник із ШІ-агентами має випустити застосунок для iPhone/iPad, а потім Android, маючи лише Windows. Потрібна одна мова для клієнта, сервера й контент-пайплайну, довгий життєвий цикл коду та можливість автоматично перевіряти архітектурні правила. Власник вимагає чистої архітектури за Робертом Мартіном.

## Варіанти

1. **.NET MAUI + Clean Architecture** (Domain / Application / Infrastructure / Presentation). Плюси: один стек C# для всього, .NET 10 LTS, MVVM-інструменти, тести без пристрою. Мінуси: віджети iOS усе одно на Swift, збірка iOS потребує macOS, менша екосистема UI-компонентів, ніж у нативних платформ.
2. Нативно Swift + Kotlin. Плюси: найкращий доступ до платформ. Мінуси: дві кодові бази, немає Swift-розробки на Windows взагалі.
3. Flutter / React Native. Плюси: велика екосистема UI. Мінуси: інша мова, ніж сервер; віджети так само нативні; власник обрав MAUI.

## Рішення

Обираємо .NET MAUI 10 на .NET 10 LTS з чотирма шарами й непорушним правилом залежностей. ViewModels є адаптерами презентації без бізнес-правил. Домен не залежить від фреймворків і покривається тестами. Платформові можливості за портами. Міграція на .NET 11 запланована на Q1 2027 до завершення підтримки MAUI 10.

## Наслідки

Плюс: спільний Domain між клієнтом і сервером (правила економіки, схема контенту). Плюс: архітектурні тести в CI блокують порушення. Мінус: Swift-розширення віджетів пишеться без локального Xcode і перевіряється лише в CI. Мінус: обмежений набір готових UI-контролів, тому дизайн-система будується власними компонентами на MIT-бібліотеках.
