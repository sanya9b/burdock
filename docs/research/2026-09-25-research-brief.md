## 1. Hard platform facts (iOS vs Android capability matrix)

| Surface / capability | iOS (17+ target) | Android (API 24+/target 36) | Consequence for the product |
|---|---|---|---|
| **Home-screen widget** | WidgetKit, Swift/SwiftUI only; MAUI cannot author it. Built in Xcode, referenced via `AdditionalAppExtensions`, data via App Group, reload via `WidgetCenter.reloadTimelines` (NuGet WidgetKit.WidgetCenterProxy 10.0.0). Widget code is *not running while on screen*; content comes from pre-computed timelines, entries ≥ ~5 min apart, budget ~40–70 reloads/day for a frequently viewed widget [https://developer.apple.com/documentation/widgetkit/keeping-a-widget-up-to-date] [https://devblogs.microsoft.com/dotnet/how-to-build-ios-widgets-with-dotnet-maui/] | AppWidgetProvider + RemoteViews written **in C#** inside `Platforms/Android` (official Microsoft guide, 2026-01-12); `updatePeriodMillis` ≥ 30 min or 0 + WorkManager (≥ 15 min); Glance has no NuGet binding; API 37 target caps RemoteViews bitmap memory (1.5×w×h×4 bytes, fatal if exceeded) [https://devblogs.microsoft.com/dotnet/how-to-build-android-widgets-with-dotnet-maui/] [https://developer.android.com/develop/ui/views/appwidgets/advanced] [https://developer.android.com/about/versions/17/behavior-changes-17] | Two native widget codebases (Swift + C#/RemoteViews); shared Domain computes a "word timeline", widgets are thin presenters. Design text/shape-first (iOS tinted/clear mode renders everything white). |
| **Lock-screen widget** | Accessory families (rectangular/circular/inline) iOS 16+, same extension; vibrant single-tint rendering; StandBy (iOS 17+) free via same widget, refreshes not budgeted [https://developer.apple.com/documentation/widgetkit/widgetfamily/accessoryrectangular] [https://developer.apple.com/documentation/widgetkit/widgetlocation/standby] | Phone lock-screen widget page only since Android 16 QPR2 (Pixel, 2025-12-02); any widget eligible unless `not_keyguard` (API 36); tapping requires unlock unless `showWhenLocked`; OEM behaviour (Samsung etc.) **unverified** [https://android-developers.googleblog.com/2025/03/widgets-on-lock-screen-faq.html] [https://developer.android.com/reference/android/appwidget/AppWidgetProviderInfo] | iOS: ship day one. Android: same widget, opt-in to keyguard, but reach is Android 16 QPR2+ only; notifications remain the main Android lock-screen surface. |
| **Notification** | Local notifications: only the 64 soonest pending survive; no "seen" callback, only taps/actions/dismiss observable; Service Extension modifies remote pushes only [https://developer.apple.com/documentation/uikit/uilocalnotification] [https://developer.apple.com/documentation/usernotifications/handling-notifications-and-notification-related-actions] | POST_NOTIFICATIONS runtime permission; BigTextStyle / DecoratedCustomViewStyle; schedule via WorkManager or `setWindow` ≥ 10 min (no exact alarms: SCHEDULE_EXACT_ALARM denied by default, USE_EXACT_ALARM Play-restricted) [https://developer.android.com/reference/android/app/AlarmManager] [https://support.google.com/googleplay/android-developer/answer/13161072] | Re-plan the schedule on every foreground; update one notification ID; rewards may never be gated on notification permission (Apple 5.1.2(i)). |
| **Live Activity / overlay** | Live Activities iOS 16.1+: ≤ 8 h active (12 h on lock screen), 4 KB state, HIG forbids passive/promotional use, App Review 4.5.3 — a "word ticker" is a rejection risk [https://developer.apple.com/documentation/activitykit/displaying-live-data-with-live-activities] [https://developer.apple.com/design/human-interface-guidelines/live-activities] | Live Updates explicitly exclude "quick access to app features / promotions"; SYSTEM_ALERT_WINDOW overlays need visible overlay on Android 15+ to start FGS, Android 12 blocks pass-through touches, Play scrutiny; AccessibilityService policy-prohibited [https://developer.android.com/develop/ui/views/notifications/live-update] [https://developer.android.com/develop/background-work/services/fgs/restrictions-bg-start] [https://support.google.com/googleplay/android-developer/answer/10964491] | Not in v1 on either platform. Only a user-started "learning session" Live Activity is HIG-compliant later. |
| **Unlock-triggered rotation** | **Impossible.** `protectedDataDidBecomeAvailable` fires only in the running process; no background strategy for unlock/screen-on [https://developer.apple.com/documentation/backgroundtasks/choosing-background-strategies-for-your-app] [https://nemecek.be/blog/104/checking-if-device-is-locked-or-sleeping-in-ios] | Only via context-registered receiver for ACTION_USER_PRESENT inside a `specialUse` foreground service (persistent notification, Play declaration + demo video, OEM battery killers); SCREEN_ON is deferred for cached apps on Android 14 [https://developer.android.com/reference/android/content/Intent] [https://developer.android.com/develop/background-work/background-tasks/broadcasts] [https://support.google.com/googleplay/android-developer/answer/13392821] | Remove "on unlock" from the cross-platform spec. Android-only opt-in "unlock mode" is a separate, later decision. |
| **Swipe-triggered rotation** | **Impossible.** WidgetKit may reload when a page becomes visible but exposes no event [https://developer.apple.com/documentation/widgetkit/keeping-a-widget-up-to-date] | No swipe event for widgets; live wallpaper `onVisibilityChanged` is the only proxy (opt-in, replaces wallpaper, cannot target lock screen alone) [https://developer.android.com/reference/android/service/wallpaper/WallpaperService.Engine] | Rotation = time cadence (15/30/60 min presets) + "Next word" tap (iOS 17 interactive `Button(intent:)` is guaranteed and unbudgeted) [https://developer.apple.com/documentation/widgetkit/adding-interactivity-to-widgets-and-live-activities]. |
| **Impression counting** | No "widget viewed" API; counting `getTimeline` over-counts; only aggregate App Store Connect "Home Screen Widget Usage" (opt-in users, up to 8 days late) [https://discussions.apple.com/thread/254552230] [https://developer.apple.com/documentation/analytics-reports/home-screen-widget-usage] | Real impressions via `AppWidgetManager.queryAppWidgetEvents` on SDK 36.1+ (clicks, scrolls, impressions; events kept only a few days, poll daily); older devices: estimate [https://developer.android.com/reference/android/appwidget/AppWidgetManager] | Domain must carry two counters: `exposureScheduled` (opportunities) and `exposureConfirmed` (tap / intent / notification action / in-app / Android 16.1 impression). Show only the confirmed number as "переглянуто". |
| **Store gates** | Since 2026-04-28 uploads need Xcode 26 / iOS 26 SDK; since 2026-09-09 deployment target ≥ iOS 13; PrivacyInfo.xcprivacy mandatory [https://developer.apple.com/news/upcoming-requirements/] [https://learn.microsoft.com/en-us/dotnet/maui/ios/privacy-manifest] | Target API 36 required since 2026-08-31 (extension to 2026-11-01); .NET 11 raises min API to 24 [https://support.google.com/googleplay/android-developer/answer/11926878] [https://learn.microsoft.com/en-us/dotnet/core/compatibility/maui/11/android-minimum-api-level] | Adoption: iOS 26 on 79% of all iPhones, iOS 18 14%, older 7% (Apple, 2026-06-07) → iOS 17 minimum costs ≤ 7% [https://developer.apple.com/support/app-store/]. |

**Pipeline** (server-side, reproducible, versioned): CEFR-J/Octanove lemmas → wordfreq bands → kaikki enrichment → LLM topic classification into app categories (confidence score) → Ukrainian translation ranking (Wiktionary candidates → LLM → human linguist) → Tatoeba/LLM examples filtered by CEFR level → offensive-tag filter (`vulgar`, `derogatory`, `slang`) → two-pass LLM QA (generate → judge) → **documented human review** (100% for A1–A2 launch set, stratified 10% for B1–C2) → immutable, ECDSA-signed SQLite/JSON **content packs** per level × topic (100–500 KB) on object storage + CDN, manifest served by API with ETag. Current Anthropic pricing: Opus 5.5 $4/$20, Sonnet 5 $2/$10, Haiku 4.5 $1/$5 per MTok, Batches −50%; Commercial Terms assign Output rights to the customer and require a "may be false" notice [https://www.anthropic.com/pricing] [https://www.anthropic.com/legal/commercial-terms]. Under Ukraine Law 2811-IX Art. 33 raw AI output has only a 25-year sui generis right (and only if source rights were respected, part 7); human-edited output is a normal work — keep the review log as evidence [https://zakon.rada.gov.ua/laws/show/2811-20/print].

**Schema** (content DB, personal-data-free): `lexeme`, `sense`, `translation`, `example`, `pronunciation`, `audio_asset`, `image_asset`, `topic`, `lexeme_topic`, `source`, `license`, `provenance` (model_id, prompt_version, reviewer, timestamps), `content_pack` (version, checksum, attributions). User-side progress keyed by `lexeme_id` in a separate store. Publish the compiled DB under CC BY-SA 4.0 with an ATTRIBUTIONS file and an in-app "Джерела та ліцензії" screen. Widget/notification surfaces cannot show attribution → exclude Tatoeba sentences from them or define attribution placement.

## 6. Learning + rewards model recommendation

**Scheduler**: FSRS-6 (21 parameters; benchmark log loss 0.3460 vs HLR 0.4694; default parameters already beat SM-2; FSRS-7 exists in benchmark but no official library or Anki release ships it — Anki 26.09.3 pins fsrs 6.6.2). Pure deterministic Domain class, injected clock, UTC + local "learning day" (rollover 04:00), desired retention 0.90 exposed as Легко 0.85 / Стандарт 0.90 / Максимум 0.94, max interval 365 d, fuzz on, append-only `ReviewLog` for future re-optimization and FSRS-7 replay; SM-2 kept only for import [https://github.com/open-spaced-repetition/srs-benchmark] [https://github.com/open-spaced-repetition/awesome-fsrs/wiki/The-Algorithm] [https://github.com/ankitects/anki/blob/main/Cargo.toml]. UI copy must make "Ще ні" clearly the *forgot* grade (Hard is a passing grade) [https://docs.ankiweb.net/deck-options.html].

**Two-track model**: passive exposure (widget/lock screen/notification) is logged as `ExposureRecord` and drives (a) an Introduction phase (≥ 3 exposures on ≥ 2 days before a word enters the in-app queue), (b) word selection (lowest retrievability first, ≤ 3–5 words/day/surface), (c) "guess first, tap to reveal" pre-testing — but **never grades the FSRS card**. Evidence: encounters → incidental learning r = .34; home-screen exposure teaches recognition (Vocabulary Wallpaper, WaitChatter); durable memory comes from retrieval with feedback, spaced across days [https://doi.org/10.1111/lang.12343] [https://doi.org/10.1145/2207676.2208598] [https://doi.org/10.1126/science.1152408] [https://doi.org/10.1111/j.1467-9280.2008.02209.x]. Note FSRS-6 is weak on same-day reviews (0.3842 with same-day data) — do not grade same-day micro-exposures.

**Testing ladder** (Laufer-Goldstein hierarchy, each maps to a grade): L1 EN→UK multiple choice with same-level/topic distractors; L2 UK→EN choice; L3 listening; L4 cloze with non-giveaway context; L5 typed EN recall (Damerau-Levenshtein ≤ 1 for ≥ 5 letters); matching = warm-up, no grade; immediate corrective feedback always; "Вивчено" = 3 correct L4/L5 recalls on ≥ 2 days and stability ≥ 21 d [https://doi.org/10.1111/j.0023-8333.2004.00260.x] [https://doi.org/10.1080/09541440601056620] [https://doi.org/10.1111/lang.12285] [https://doi.org/10.1037/a0023956].

**Intake**: default 10 new words/day (options 3/5/10/15/20), workload projector (Anki heuristic: 20 new ≈ 200 reviews/day), auto-throttle when backlog > 3 days ("Рюкзак повний — спочатку повторимо"); one mixed session beats topic-split micro-sets (set size irrelevant, spacing matters) [https://doi.org/10.1017/S0272263115000236]. No RCT fixes a number — treat as tunable policy.

**Streaks & rewards (ethical Duolingo)**: learning day = ≥ 5 graded cards; streak modes Щоденний / Гнучкий (N days/week, default 5); 1 free freeze/week (max 2), earned 48-h repair, Пауза up to 14 days; milestone celebrations respect Reduce Motion; notification copy habit-framed (+5% opt-in at Duolingo), 1/day cap, quiet hours, never loss-framed [https://blog.duolingo.com/improving-the-streak/] [https://blog.duolingo.com/how-duolingo-streak-builds-habit/] [https://blog.duolingo.com/putting-in-work-the-habit-of-language-learning/]. Economy: XP (non-spendable) + "реп'яшки" soft currency earned only for learning actions with daily caps, spent only on cosmetics/streak flexibility, no randomized rewards, no purchasable currency (avoids Apple 3.1.1 / Play odds disclosure), no hearts, no leagues, no fake urgency/confirmshaming; 7-day login calendar 5/5/10/10/15/15/30 (pauses, never resets) + 30-day track with a deterministic theme; ~22 learning-aligned micro-tasks (3 daily + 1 weekly). Deci et al. 1999: expected tangible rewards undermine intrinsic motivation — keep rewards informational and cosmetic [https://doi.org/10.1037/0033-2909.125.6.627] [https://developer.apple.com/app-store/review/guidelines/] [https://support.google.com/googleplay/android-developer/answer/9858738] [https://www.deceptive.design/types]. Ledger = append-only signed `LedgerEvent` stream folded by pure `EconomyRules` so the same code becomes server-authoritative later. A first-class "без гейміфікації" switch. No time limits by default (WCAG 2.2.1), no flashing > 3/s, rewards never by colour/sound alone [https://www.w3.org/WAI/WCAG22/Understanding/timing-adjustable.html] [https://gameaccessibilityguidelines.com/full-list/].
